# 🆕 Brand-Prefix Ambiguity Fix + Unified Generic-Word Filtering (October 2026):
# ├── get_certifications STEP 2 guard        # Gathers ALL partial matches when no category is given
# ├── get_certifications STEP 1 guard        # Now gathers ALL brand+category matches, not just the first
# ├── match_type="ambiguous_brand"           # Response when multiple brands share a prefix, with or without category
# ├── Removed _find_exact_brand_category_match()  # Its only caller (STEP 1) now inlines the gather-then-decide logic
# ├── is_brand_token() helper                # Single source of truth for generic-vs-identifying
# ├── _improved_partial_match()              # Two-content-word rule (see below)
# ├── find_parent_company()                  # Pass 2 first-word anchor respects is_brand_token
# ├── extract_brand_from_product_text()      # Candidate keys filtered through is_brand_token
# ├── GENERIC_WORDS extended                 # +22 words, grouped by kind (marketing, natural-world, venues, titles, proper names)
# ├── Plural variants added                  # "ellas", "caffe" — sheet uses plural/foreign forms
# ├── _check_alias_maps_for_generic_keys()   # Startup warning if BRAND_ALIASES/BRAND_SYNONYMS keys are generic
# ├── Frontend: searchProduct() handler      # Shows ambiguous_brand note as error banner
# ├── Frontend: displayResults() guard       # Early return for ambiguous_brand before rendering
# └── Frontend: success-banner exclusion     # Success banner skipped on ambiguous_brand and category_required
#
# What this fixes:
# - Searching "Chobani" returned "Chobani Oat" certifications silently.
#   Now returns: "Multiple brands match 'Chobani': chobani oat,
#   chobani yogurt. Please be more specific."
# - Parent brand with two products in the same category no longer
#   silently resolves to the first: "Chobani" + en:dairies with both
#   Chobani Yogurt and Chobani Oat Milk in the sheet now returns
#   ambiguous_brand listing both.
# - Generic words like "earth", "love", "ella", "cafe" no longer
#   anchor to a parent company or brand key just because they appear
#   as the first word of an unrelated multi-word brand.
#
# Design: every prefix-based matcher now consults the same
# generic-word boundary via is_brand_token(). Adding a word to
# GENERIC_WORDS affects all matchers at once. No matcher reads
# GENERIC_WORDS directly except the helper. STEP 1 and STEP 2 of
# get_certifications use the same gather-then-decide pattern, so the
# response shape is consistent whether the caller supplied a
# category or not.

# ├── Sheet conflict resolution               # 21 manually-reviewed (brand, category) conflicts resolved to chosen cert values
# ├── Corporate suffix strip                  # "Inc", "LLC", "Ltd", "Limited", "Corporation", "Corp" removed from Product_Brand across 348 rows

# ├── Sheet row count: 4,346 → 3,959          # Workbook / CSV after cleanup
# ├── Loaded record count: 3,898              # Distinct normalized brand keys after load
# │
# ├── BrandNormalizer.normalize(): "the" preserved          # The article is part of the brand name ("The Honest Company")
# ├── BrandNormalizer.normalize(): suffix strip guarded     # Refuses any strip that would reduce a multi-word name to a single content word
# │                                                          # "The Honest Company" stays "the honest company"
# │                                                          # "Best Foods" stays "best foods"
# │                                                          # "Candy Co, LLC" stays "candy co"
# ├── Replacement order: punctuation first, then strips     # So the content-word guard sees the final word form
# ├── Longest-phrase-first iteration                         # " company" tried before " co"
# ├── FUNCTION_WORDS set added                               # Articles, conjunctions, prepositions, pronouns
# │                                                          # Distinct from GENERIC_WORDS content words (honest, best, candy, company, foods)
# ├── _content_word_count() helper                          # Counts non-function words
# ├── _improved_partial_match(): two-content-word rule      # Two shared content words → match, even if both are in GENERIC_WORDS
# │                                                          # "Honest Company" matches "the honest company"
# │                                                          # Single generic word → still requires category pairing
# └── "bare" added to GENERIC_WORDS                         # "Bare" does not match "The Bare Home" alone
#
# What this fixes:
# - 47 non-brand-token keys down to 12. All remaining offenders are
#   real brands whose names are single generic words, or single-word
#   brands: Bare, CL, Freshly, KIND, LU, Naturally, O?, Premium,
#   V8, Wellness, Wise, Zo?.
# - Brands like "The Honest Company", "Best Foods", "Candy Co",
#   "Grove Co", "Co North", "Tea Group", "International Coffee Co."
#   now normalize to multi-content-word keys instead of single
#   generic-word keys.
# - A user typing "Honest Company" (without "The") matches the key
#   "the honest company" via the two-content-word rule. The response
#   carries brand_was_corrected: true and canonical_brand.
# - A user typing "The Honest Company" exact-matches the key.
#
# Design: GENERIC_WORDS describes words that cannot identify a brand
# alone. FUNCTION_WORDS is the narrower subset — articles,
# conjunctions, prepositions, pronouns — that carry no brand
# meaning at all, even in combination. The normalizer uses
# content-word counts (total words minus function words) to decide
# when a suffix strip would destroy a distinctive pairing.
#
